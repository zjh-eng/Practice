## 三、数据集:MNIST

- **内容**:0~9 共 10 类手写数字
- **规模**:60,000 张训练图 + 10,000 张测试图
- **尺寸**:28×28 单通道灰度图
- **预处理**:`ToTensor`(归一化到 [0,1])+ `Normalize`(均值 0.1307、标准差 0.3081)
- **划分**:训练集按 9:1 切出验证集,测试集独立用于最终评估

## 四、模型结构:CNN

采用「两层卷积 + 两层全连接」的经典 CNN,总参数量 **421,642(约 0.42M)**。

```
Input [1, 28, 28]
  → Conv(1→32, 3×3) → ReLU → MaxPool(2)     # 28×28 → 14×14
  → Conv(32→64, 3×3) → ReLU → MaxPool(2)    # 14×14 → 7×7
  → Flatten → FC(3136→128) → ReLU → Dropout(0.5)
  → FC(128→10)
```

**设计要点**:卷积层负责提取局部特征,池化下采样压缩维度,全连接层完成分类;
Dropout 用于抑制过拟合。

## 七、错误样本分析

对 84 个错误样本做了归类统计,发现错误主要集中在**字形相近的数字**之间:

| 排名 | 混淆对(真值 → 预测) | 次数 |
|---|---|---|
| 1 | 4 → 9 | 11 |
| 2 | 3 → 5 | 8 |
| 3 | 2 → 7 | 6 |
| 4 | 7 → 2 | 5 |
| 5 | 9 → 5 | 4 |

**分析结论**:4 与 9、3 与 5、2 与 7 这几组数字在手写体中笔画形态容易变形、
高度相似,是 CNN 出错的主要方向。错误样本可视化见下图。

![错误样本可视化](../outputs/week1/error_analysis.png)

## 九、遇到的问题与解决

| 问题 | 原因 | 解决方案 |
|---|---|---|
| 导入 torch 报 `libiomp5md.dll already initialized` | Windows 下 numpy(MKL)与 torch 的 OpenMP 运行库重复 | 脚本顶部设置 `KMP_DUPLICATE_LIB_OK=TRUE` |
| PyCharm 运行路径错乱 | 脚本用了相对路径,而 PyCharm 工作目录默认为项目根目录 | 改为基于 `__file__` 推导项目根目录 |
| conda 新建环境安装 PyTorch 失败 | Windows 260 字符路径上限导致解压失败 | 复用已有 GPU 环境 `tuduipytorch` |
