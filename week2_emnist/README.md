# 第2周 · EMNIST 字符识别

## 目标
从数字识别扩展到「字母 + 数字」混合识别,并完成多模型对比实验。

## 数据集

- **EMNIST `balanced` 子集**:47 类(数字 0-9、大写 A-Z、以及 11 个未合并的小写字母)
- 训练集 112,800 张 + 测试集 18,800 张,28×28 灰度图
- 类别列表:`0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabdefghnqrt`

### 两个必须处理的坑

1. **图像方向**:EMNIST 原始 idx 文件以「转置」形式存储,torchvision 直接读取会得到
   **旋转 90°** 的图。本项目在 transform 中交换 H/W 修正,并用 `check_data.py`
   打印字符画实测验证(不修正时「3」是躺倒的)。
2. **标签偏移**:只有 `letters` 子集标签从 1 开始,本项目选用的 `balanced` 无此问题。

## 文件说明

| 文件 | 作用 |
|---|---|
| `models.py` | 三种模型:MLP、CNN(3层卷积+BN)、ResNet18(适配28×28输入) |
| `common.py` | EMNIST 数据加载、数据增强、设备与随机种子 |
| `check_data.py` | 数据校验:字符画验证图像方向是否修正正确 |
| `train.py` | 训练脚本,支持 `--model` / `--augment` 切换,记录三项对比指标 |
| `compare.py` | 汇总各模型结果,生成对比表(Markdown)和对比图(PNG) |
| `run_all.sh` | 一键跑完全部对比实验 |

## 运行

```bash
conda activate tuduipytorch
cd week2_emnist

python check_data.py 3          # 校验数据方向
python train.py --model cnn     # 单模型训练
bash run_all.sh                 # 一键跑完整套对比实验
```

## 实验结果(第2周验收物)

数据集:EMNIST balanced(47 类) | 训练 15 轮 | batch size 128 | 学习率 1e-3

| 模型 | 数据增强 | 测试准确率 | 训练时间(s) | 每轮耗时(s) | 参数量 |
|---|---|---|---|---|---|
| MLP | 否 | 83.40% | 252.2 | 16.8 | 545.3 K |
| CNN | 否 | 89.06% | 308.9 | 20.6 | 400.4 K |
| CNN | 是 | 88.80% | 876.8 | 58.5 | 400.4 K |
| ResNet18 | 否 | 89.14% | 1852.7 | 123.5 | 11.192 M |
| **ResNet18** | **是** | **90.02%** | 2277.6 | 151.8 | 11.192 M |

对比图见 `outputs/week2/comparison.png`,对比表见 `outputs/week2/comparison.md`。

## 结果分析

### 1. CNN 用更少的参数,比 MLP 高 5.66 个百分点

CNN(40.0 万参数)比 MLP(54.5 万参数)**参数更少,准确率却高出 5.66%**。
原因是卷积的**权值共享 + 局部连接**:同一个 3×3 卷积核在整张图上滑动复用,
参数量与图像大小无关;而 MLP 展平后每个像素都要独立连一个权重,既参数多又丢失了
空间结构。这说明**结构设计比参数量更重要**。

### 2. ResNet18 参数多 28 倍,准确率只高 0.08%,而且已经过拟合

| 模型 | 参数量 | 末轮训练准确率 | 最优验证准确率 | 差距 |
|---|---|---|---|---|
| CNN | 0.40 M | 90.1% | 89.2% | ~1 点 |
| ResNet18 | 11.19 M | **95.7%** | 89.0% | **~6.7 点** |

ResNet18 训练准确率一路涨到 95.7%,验证准确率却卡在 89% 不再上升,
验证损失几乎不降(0.4246 → 0.4224)——这是典型的**过拟合**。
即:ResNet18 的容量对这个任务来说**过剩**了,多出来的参数只是在「死记」训练集,
并没有学到更多可泛化的特征。代价是**训练时间是 CNN 的 6 倍**。

### 3. 数据增强的效果取决于模型是否过拟合(本周最有价值的发现)

同样是加数据增强,两个模型的结果**完全相反**:

| 配置 | 测试准确率 | 变化 | 训练时间 | 时间变化 |
|---|---|---|---|---|
| CNN | 89.06% | — | 308.9s | — |
| CNN + 增强 | 88.80% | **-0.26%**(几乎无变化) | 876.8s | **×2.8** |
| ResNet18 | 89.14% | — | 1852.7s | — |
| ResNet18 + 增强 | **90.02%** | **+0.88%**(明确提升) | 2277.6s | ×1.23 |

**为什么差这么多?** 把两件事放在一起看就清楚了:

| 模型 | 是否过拟合 | 增强的效果 |
|---|---|---|
| CNN | 否(训练 90.1% vs 验证 89.2%,仅差 1 点) | 无效(-0.26%,属波动范围) |
| ResNet18 | **是**(训练 95.7% vs 验证 89.6%,差 6.1 点) | **有效(+0.88%)** |

数据增强的作用机制是**抑制过拟合**——它通过制造「同一张图的不同变形」来增加
数据的有效多样性,逼模型学习更本质的特征而非死记样本。因此:

- CNN **本来就没过拟合**,没有可抑制的对象,增强自然无效,只是白白增加计算;
- ResNet18 **严重过拟合**,增强正好对症下药:加入增强后,训练末轮准确率与最优
  验证准确率的差距从 **6.1 点收窄到约 0**,测试准确率提升 0.88%,成为全场最优模型。

**关于增强的额外开销**:增强在 CPU 上做几何变换(`RandomAffine` + `RandomErasing`),
绝对开销约为每轮 28~38 秒,与模型无关。但它的**相对代价**取决于模型本身有多重:
CNN 基线只要 20.6s/轮,所以慢了 2.8 倍;ResNet18 基线要 123.5s/轮,只慢了 1.23 倍。

> **结论:数据增强不是万能药。它只在模型开始过拟合时才有明显收益——**
> **必须先诊断「过拟合是不是当前的瓶颈」,再决定要不要用。**

### 4. 综合结论

1. **结构比参数量重要**:CNN 用比 MLP 少 26% 的参数换来 +5.66% 的准确率,
   说明卷积的权值共享与局部连接是更高效的特征提取方式。
2. **堆深度在本题收益极小**:ResNet18 参数量是 CNN 的 28 倍,不加增强时仅高 0.08%,
   且明显过拟合。瓶颈不在参数量,而在任务本身的难度与数据规模。
3. **数据增强要对症下药**:CNN 加增强无效(-0.26%),ResNet18 加增强有效(+0.88%)。
   差别源于两者是否过拟合——**增强只在过拟合时才有价值**。
4. **最优方案**:ResNet18 + 数据增强(90.02%),但代价是 11.2M 参数与 2277.6s 训练时间;
   **若考虑性价比,CNN 是更好的选择**——参数仅 1/28、训练快 7 倍,准确率只低 0.96 个百分点。

### 5. 可继续探索的方向

- 增强策略仍然较粗放(几何变换 + 遮挡),可尝试更贴合手写特点的增强(如弹性形变);
- 当前每轮耗时受限于 CPU 端的数据增强,可通过多进程数据加载(`num_workers`)缓解;
- 15 轮训练下 ResNet18 仍未完全收敛,可延长训练并配合学习率衰减进一步验证。
